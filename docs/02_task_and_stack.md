# MiniRTOS 核心笔记（二）：任务控制块与任务栈伪造初始化

本文档记录 MiniRTOS 开发阶段一中关于**任务控制块 (`TCB_t`)**、**Cortex-M 任务栈帧伪造 (`pxPortInitialiseStack`)** 与 **静态任务创建 (`xTaskCreateStatic`)** 的底层原理。

---

## 1. 为什么需要“伪造任务栈 (Stack Forgery)”？

在 RTOS 中，全新的任务从未在 CPU 上实际运行过，但调度器的切换逻辑统一假设所有任务都是在中断里被切走的：
> **调度器切换逻辑**：从 `pxCurrentTCB->pxTopOfStack` 指向的栈地址中，按顺序恢复（POP）出 CPU 的 16 个核心寄存器 (R0~R15, xPSR)。

为了让调度器能够以完全统一的代码启动一个新任务，必须在任务创建时在任务栈内存中**预先填充（伪造）**一套符合 ARM Cortex-M 异常中断压栈规范的初始寄存器数据。

---

## 2. ARM Cortex-M 栈帧物理内存布局

ARM 栈在 Cortex-M 上为**满递减栈（Full Descending Stack）**，即压栈时栈顶指针 `pxTopOfStack` 向低地址生长。

压入栈帧由两部分组成，共 16 个 32 位寄存器（占 64 字节）：

```text
高地址 (栈底 / puxStackBuffer[ulStackDepth - 1])
  │   [ xPSR ]  ──► 0x01000000 (Bit 24 必须置 1, 强制 CPU 处于 Thumb 状态)
  │   [  PC  ]  ──► pxCode (任务入口 C 函数地址, 恢复后 CPU 直接跳转运行)
  │   [  LR  ]  ──► 0x00000000 (任务退出异常返回地址)
  │   [ R12  ]  ──► 0x12121212 (调试魔数)
  │   [  R3  ]  ──► 0x03030303
  │   [  R2  ]  ──► 0x02020202
  │   [  R1  ]  ──► 0x01010101
  │   [  R0  ]  ──► pvParameters (C 语言 AAPCS 调用约定：R0 传递第一个参数指针)
  ├───────────────────────────────────────────────── (硬件自动压栈帧 8 个 Word)
  │   [ R11  ]  ──► 0x11111111
  │   [ R10  ]  ──► 0x10101010
  │   [  R9  ]  ──► 0x09090909
  │   [  R8  ]  ──► 0x08080808
  │   [  R7  ]  ──► 0x07070707
  │   [  R6  ]  ──► 0x06060606
  │   [  R5  ]  ──► 0x05050505
  ▼   [  R4  ]  ──► 0x04040404
低地址 (当前 pxTopOfStack 指针停留处)
```

## 3. 静态任务创建 (`xTaskCreateStatic`) 关键设计点

### 3.1 8 字节对齐 (AAPCS 规范)
ARM 过程调用标准 (AAPCS) 规定：进入中断服务程序及函数调用时，SP 栈指针必须保持 **8 字节对齐**。
```c
pxTopOfStack = ( StackType_t * ) ( ( ( uintptr_t ) pxTopOfStack ) & ( ~( ( uintptr_t ) 0x0007 ) ) );
```
通过按位与 `~0x0007` 清除低 3 位，确保计算出的栈顶指针满足 8 字节对齐要求。

### 3.2 节点与 Owner 绑定
```c
vListInitialiseItem( &( pxNewTCB->xStateListItem ) );
listSET_LIST_ITEM_OWNER( &( pxNewTCB->xStateListItem ), pxNewTCB );
```
将 TCB 内部的状态节点 `xStateListItem` 初始化，并将其 `pvOwner` 指向 `pxNewTCB`，以便后续调度器将该节点加入就绪列表后，能通过节点反查到任务 TCB。
